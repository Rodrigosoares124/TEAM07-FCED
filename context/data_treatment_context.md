# Audit of the data treatment

## 1. Scope of this audit

This document audits the data-preparation work in
[`00_scope_definition.ipynb`](/home/jquental/Desktop/STAT_proj/TEAM07-FCED/00_scope_definition.ipynb)
and defines the treated data structure to use in the next stages of the project.
The audit concerns the preparation of the SGIF/ICNF wildfire records for Braga,
Guimarães, Guarda, and Faro from 2001 through 2025. It does not interpret the
results of hypothesis tests, because the notebook stops before inferential
analysis.

## 2. What the notebook does

The preparation pipeline is, in general, coherent and aligned with the stated
research questions:

1. Reads the three CSV files in `dados/`, using semicolon separators,
   comma-decimal notation, and UTF-8 with BOM support.
2. Concatenates the files into one table of **497,478 records** and standardizes
   the original column names by trimming whitespace and converting them to
   uppercase.
3. Creates a normalized municipality key from `CONCELHO` by uppercasing,
   trimming whitespace, and removing accents. This correctly makes
   `Guimarães` match `GUIMARAES` without changing the displayed source value.
4. Restricts the study population to the four municipalities:
   `BRAGA`, `GUIMARAES`, `GUARDA`, and `FARO`.
5. Creates `ANALYSIS_YEAR`, using the year parsed from `DATAHORAALERTA` when
   that column is available.
6. Standardizes the cause field into uppercase `CAUSE` values and maps empty
   values to `DESCONHECIDA`. It also creates `MISSING_CAUSE` to retain the
   information that the cause is unavailable.
7. Calculates `INTERVENTION_TIME_MINUTES` from the alert timestamp to the first
   intervention timestamp.
8. Creates the period classification:
   - `2001-2016`: pre-2017;
   - `2017`: transition year;
   - `2018-2025`: post-2017.
9. Checks counts by year and municipality, cause composition, missingness,
   intervention-time distributions, and the negligent-versus-intentional
   contingency table.
10. Selects a documented set of required columns, producing a row-level table
    with **15,534 records and 11 columns**.

## 3. Audit findings

### Strengths

- **The study population is explicit.** The selected municipalities and years
  are defined in code rather than being left to manual filtering.
- **Municipality matching is robust to accents and case.** The normalized key
  avoids losing Guimarães records because of spelling differences.
- **The transition-year decision is explicit.** 2017 is retained in the treated
  data but is excluded from the before/after comparison table.
- **Unknown causes are not silently deleted.** They are retained as
  `CAUSE = DESCONHECIDA` and marked with `MISSING_CAUSE = True`.
- **Quality checks are relevant to the research questions.** The notebook checks
  the exact variables used to define cause, annual counts, intervention time,
  and burned area.
- **The final column selection is defensive.** The notebook raises an error if
  any required treated variable is missing before creating the final table.

### Issues and limitations to carry forward

1. **`ANALYSIS_YEAR` is not fully implementing the stated fallback.** The
   narrative says that `ANO` is used when the alert date is unavailable or
   invalid. In the executed code, the fallback to `ANO` is only used when
   `DATAHORAALERTA` is absent; invalid or missing alert dates remain as a
   missing `ANALYSIS_YEAR`. The current outputs show all years 2001--2025, but
   the intended rule should still be implemented explicitly before the final
   export.

2. **The final row-level table is not actually exported.** The CSV export cell
   is commented out. Therefore, the treated dataset currently exists only in
   notebook memory and must be regenerated by executing the notebook. A
   reproducible project should save the final row-level table, preferably with
   an explicit output path and a documented generation step.

3. **The raw record identifier is discarded.** The selected columns do not
   include `CODIGO_SGIF` or another source identifier. This makes it harder to
   trace a treated row back to the source files or to detect duplicates. The
   identifier should be retained in the canonical treated dataset if it is
   available and unique enough for provenance.

4. **The cause recoding is appropriate for the stated comparison but lossy.**
   `DESCONHECIDA` combines blank/not-investigated records with cases whose
   investigated cause could not be determined. The `MISSING_CAUSE` flag
   preserves the broad exclusion status, but it does not distinguish those two
   mechanisms. If that distinction matters later, retain the original
   `TIPOCAUSA` and add a separate missingness classification.

5. **The treatment does not validate duplicates across source files.** The
   three files have complementary year ranges in their names, but the pipeline
   does not verify uniqueness of `CODIGO_SGIF` or compare overlapping records.
   A duplicate check should be run before inferential analysis.

6. **The density calculation is a summary, not a row-level variable.** The
   function correctly returns municipality-level counts, area, number of years,
   and ignition density. However, the density output is not merged into the
   15,534-row table. It should be maintained as a separate municipality-period
   summary table, or generated from an explicitly documented aggregation.

7. **The annual analysis table is displayed but not materialized.** The
   crosstab gives counts by `ANALYSIS_YEAR` and `MUNICIPALITY`, but there is no
   final long-format table with one row per municipality-year. That table is
   the natural input for the annual-count t-test and the municipality ANOVA.

8. **The intervention-time check is descriptive only.** The output reports no
   negative values and no values above 24 hours among non-missing observations.
   It does not, however, remove or otherwise resolve missing intervention
   times. Missingness is appropriate for records with no timestamp, but the
   denominator must be stated whenever intervention time is analyzed.

9. **The treatment covers all cause categories, while RQ1 uses only two.**
   `NATURAL`, `REACENDIMENTO`, and `DESCONHECIDA` remain in the canonical table,
   which is correct for preserving the population. The cause-comparison
   analysis must use a clearly labelled derived subset containing only
   `INTENCIONAL` and `NEGLIGENTE`; those categories must not be interpreted as
   all fires.

## 4. Final treated data to use moving forward

The canonical treated dataset should be a **row-level occurrence table**:
one row per SGIF ignition record in the four selected municipalities, retaining
all 15,534 in-scope records, including records with unknown causes.

### 4.1 Canonical row-level schema

| Column | Role and expected meaning |
|---|---|
| `CODIGO_SGIF` *(recommended addition)* | Source record identifier for traceability and duplicate checks. |
| `MUNICIPALITY` | Normalized municipality key: `BRAGA`, `GUIMARAES`, `GUARDA`, or `FARO`. |
| `ANALYSIS_YEAR` | Integer year used in the analysis, preferably parsed from the alert date with an explicit fallback to `ANO`. |
| `PERIOD` | Ordered category: `2001-2016`, `2017`, or `2018-2025`. |
| `DATAHORAALERTA` | Original alert date and time. |
| `DATAHORA_PRIMEIRAINTERVENCAO` | Original first-intervention date and time. |
| `DATAHORA_EXTINCAO` | Original extinction date and time. |
| `CAUSE` | Uppercase normalized cause: `INTENCIONAL`, `NEGLIGENTE`, `NATURAL`, `REACENDIMENTO`, or `DESCONHECIDA`. |
| `MISSING_CAUSE` | Boolean flag identifying records without an attributable cause. |
| `AREATOTAL_HA` | Total burned area in hectares. |
| `INTERVENTION_TIME_MINUTES` | Difference between first intervention and alert, in minutes; missing when either timestamp is unavailable. |
| `DURACAO_HORAS` | Fire duration in hours. |

The notebook currently produces all columns in this table except the
recommended source identifier. Its current finalized shape is therefore
`(15534, 11)`. The pandas index is not an analytical field and must not be
treated as an identifier when exporting.

### 4.2 Derived analytical tables

The row-level table should remain the source of truth. For analysis, create
separate derived tables rather than overwriting it:

#### Annual counts: one row per municipality-year

| Column | Meaning |
|---|---|
| `MUNICIPALITY` | Municipality |
| `ANALYSIS_YEAR` | Year |
| `PERIOD` | Pre-2017, 2017, or post-2017 |
| `IGNITIONS` | Number of row-level records in that municipality-year |
| `AREA_KM2` | Municipality area |
| `IGNITION_DENSITY_IGNITIONS_KM2_YEAR` | `IGNITIONS / AREA_KM2`; for multi-year summaries, divide by the number of included years as documented |

This is the table to use for annual-count comparisons. It preserves the
municipality-year unit of observation and prevents the t-test or ANOVA from
mistakenly treating individual ignition records as independent annual
observations.

#### Cause-comparison subset: one row per qualifying ignition

Filter the canonical table to:

```text
CAUSE in {INTENCIONAL, NEGLIGENTE}
PERIOD in {2001-2016, 2018-2025}
```

Keep `MUNICIPALITY`, `ANALYSIS_YEAR`, `PERIOD`, and `CAUSE` at minimum. The
2017 records and all other cause categories remain in the canonical table but
are excluded from this specific comparison.

#### Cause counts: one row per municipality-period-cause

Aggregate the cause-comparison subset into:

| Column | Meaning |
|---|---|
| `MUNICIPALITY` | Municipality |
| `PERIOD` | `2001-2016` or `2018-2025` |
| `CAUSE` | `INTENCIONAL` or `NEGLIGENTE` |
| `IGNITIONS` | Count of qualifying records |

The notebook’s current counts are:

| Municipality | Period | Intentional | Negligent |
|---|---|---:|---:|
| Braga | 2001-2016 | 60 | 113 |
| Braga | 2018-2025 | 85 | 48 |
| Faro | 2001-2016 | 9 | 113 |
| Faro | 2018-2025 | 33 | 117 |
| Guarda | 2001-2016 | 137 | 454 |
| Guarda | 2018-2025 | 66 | 147 |
| Guimarães | 2001-2016 | 35 | 145 |
| Guimarães | 2018-2025 | 167 | 221 |

These are counts of **known negligent or intentional causes**, not percentages
of all fires. Any proportion should state its denominator explicitly.

## 5. Validation status

Based on the executed notebook outputs:

- The combined source data contains 497,478 records.
- The four-municipality scope contains 15,534 records.
- The four municipality labels are matched successfully after normalization.
- All years from 2001 to 2025 appear in the scoped annual table.
- The cause table contains 15,534 records across five normalized categories.
- The cause-comparison table excludes 2017 and contains only negligent and
  intentional records.
- No negative intervention times or intervention times above 24 hours were
  reported among the calculated values.
- Missingness is substantial and structured, especially for cause information
  and early first-intervention timestamps; it must be reported rather than
  assumed to be random.

## 6. Recommended next step

Before running inferential tests, implement the explicit `ANO` fallback,
retain `CODIGO_SGIF` where available, check duplicates, export the canonical
row-level treated table, and materialize the municipality-year and
municipality-period-cause summaries. The canonical table should be used for
traceability and descriptive work; the aggregated tables should be used for
tests whose unit of observation is a year or a municipality-period.
